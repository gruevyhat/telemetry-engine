# M3 demo — Traveller import: sample character, sample sector, one trade turn

## What this proves

Spec §21.3's M3 acceptance list, all three items:

1. **Traveller import round-trips travtools JSON.** `packages/plugin-traveller/src/character.ts`'s
   `importCharacter`/`exportCharacter`, driven through the real shipped `CharacterImport` UI
   component (`packages/ui-shared/src/setup/CharacterImport.tsx`), against the committed
   `fictional-merchant.json` fixture.
2. **INV-9 green over imported sector data.** The real shipped `SectorImport` component
   (`packages/ui-shared/src/setup/SectorImport.tsx`) imports the committed
   `fictional-sector.sec` fixture; the resulting `TravellerSector`'s real charted distance feeds
   `resolveInformationHorizon` and `renderFeed`, and the shown price is asserted to equal the
   real historical price at that real distance — not a fabricated or hardcoded one.
3. **Trust-mode path tested with no data loaded.** The same horizon/feed path with no sector,
   asserted to report `uncounted` and render no price line at all — never a fabricated distance.

All three are proven by `tests/integration/m3-trade-turn.test.tsx`, which drives the real,
shipped modules together (real UI components' file-input handlers, real
`resolveInformationHorizon`, real `renderFeed`, real `market.tick` facts) rather than calling one
function in isolation or standing in a fake for the UI layer.

## Known limit of this document — read before running anything else

**The shipped browser app does not yet wire the Traveller plugin, sector import, or character
import into a running trade turn.** `packages/ui-shared/src/App.tsx` runs a real trade-campaign
phase script through the real interpreter (see `docs/demos` precedent and
`tests/integration/trade-campaign.test.tsx`), but its market feed calls
`renderFeed(facts, hex, currentTime.day, 0, GOODS)` — a **hardcoded** distance of `0`
(same-market, no staleness), never the imported sector's real distance or the Traveller plugin's
`travel`/`economy` at all. `resolveInformationHorizon` (M3-05), the function that turns a real
distance into trust-mode/charted/uncounted state, has **no caller anywhere in the shipped
application** — its only callers, before this card, were `packages/engine/src/economy/
horizon.test.ts` and `tests/integration/m3-horizon.test.ts`. `packages/ui-shared/src/setup/
SectorImport.tsx`, `CharacterImport.tsx`, and `Roster.tsx` (M3-10) are real, tested components,
but nothing mounts them inside `App.tsx`; a person opening the app today cannot import a sector
or a character at all.

This is not a small wiring gap: **M3's headline capability — real imported-sector distance
driving the information horizon a player actually sees — is unreachable from the running app.**
No M3 card's owned paths included `App.tsx` (M3-11 was `Plugin` assembly only; M3-10 was the
import components only). Per this card's own instruction ("run record honesty is not optional... a
fabricated pass is worse than an honest blank") and Plan §6.2 ("a milestone does not close until
its demo passes"), this document does not claim a browser walkthrough that cannot happen. What
follows is the walkthrough of the **integration test above**, plus the exact commands to run it —
real, runnable, proving the three acceptance items at the module level — not a click-through of
`App.tsx`.

**Recommendation to the owner:** authorize a follow-up card (wiring `travellerPlugin` +
sector-driven distance into `App.tsx`, a product-behavior change to the app entry point — the
two-tier method's own review gate names this as needing the human gate) before M3 formally
closes, or accept this as a documented deviation the way M2's real-device walkthrough was
deferred. This is the owner's call, not a decision made by this card.

## Walkthrough (module-level, per the Known limit above)

```sh
pnpm test:integration -- tests/integration/m3-trade-turn.test.tsx
```

1. **Character round-trip.** The test renders `<CharacterImport>`, feeds it
   `fictional-merchant.json` through its real file input, and confirms the resulting crew member
   equals what `importCharacter` produces calling it directly, and that `exportCharacter` on the
   imported result reproduces the original JSON exactly (byte-for-byte object equality) —
   confirms `career: "merchant"` (lowercase, as travtools actually exports it — this fixture is
   also what found and fixed the M3-09 case-sensitivity bug logged in PROJECT.md).
2. **Charted distance, real historical price.** The test renders `<SectorImport>`, feeds it
   `fictional-sector.sec` through its real file input, takes the first two worlds the fixture
   defines, and confirms `resolveInformationHorizon` reports `charted` with the sector's own real
   distance between them — then confirms `renderFeed` at that distance shows the price recorded
   exactly that many weeks ago, not today's price and not a fabricated one.
3. **Trust mode, no data loaded.** The same horizon/feed path with a bare `{distance: () =>
   'unknown'}` in place of a loaded sector: `uncounted`, zero price lines rendered.
4. **Commands exist.** The test reads this repo's own `package.json` and asserts every command
   this document tells the reader to run is a real script, not a fabricated one.

## Pass criteria

- All three `tests/integration/m3-trade-turn.test.tsx` describe blocks pass.
- The character round-trip is exact (`toEqual`), not approximate.
- The charted-distance price equals the real historical `market.tick` value at the real distance
  the sector fixture defines — computed by the same `marketAt`/`feedLine` functions the shipped
  renderer uses, not duplicated math.
- The uncounted path never renders a price line.
- Every clean-checkout command exits successfully.

## Known gaps (not covered by this walkthrough)

- **No browser walkthrough of import + a rendered trade turn.** See "Known limit" above — this is
  the headline gap this card exists to surface, not a minor omission.
- **`Plugin.economy`/`Plugin.travel` (M3-11) are never read by `App.tsx`.** The shipped app's
  `GOODS`/distance are its own hardcoded constants, independent of any plugin.
- **Manual character entry** (the "or on paper in 1981" path, rulebook §13.1) is unit-tested
  (M3-10) but not exercised by this walkthrough, which uses JSON import only.
- **Career edges (M3-09)** are unit- and integration-tested (`edges.test.ts`,
  `m3-plugin-assembly.test.ts`) but not exercised here — this walkthrough is the trade-turn/
  distance acceptance list specifically, not every M3 module.
- **This walkthrough's automated portion has been run** (see Run record), but the browser-level
  claim in Plan §5's exit-demo language ("completes one locally rendered trade turn") has not,
  because there is currently no browser path that does this — see Known limit.
