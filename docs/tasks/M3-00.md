# M3-00 — Travel and import decision map + design doc

## Objective
Produce `docs/design/travel-and-import-v1.md` recording every boundary M3's other packets
depend on, so no downstream packet has to guess. No production code.

## Context
M3 is "Distance + BYO characters" (Spec §22). `packages/plugin-traveller/src/index.ts` is
literally `export {}` today, and `packages/engine/src/plugin-api/index.ts` carries only
`EconomyPluginApi { goods }` — so M3 stands up most of Spec §15's `Plugin` interface for the
first time. Mirrors M0-00 and M2-00: decisions first, then code against them.

## Owner decisions already made (2026-07-25, record these, do not relitigate)
1. **Sector fixture is fictional.** Tests and the exit demo parse an invented SEC-format sector
   with original world names/UWPs. No third-party map data enters the repo; real travellermap
   exports are user-imported at runtime only, matching Spec §15's "user-driven import, stored
   locally" and its "original entries only" fair-use hygiene.
2. **Character format targets travtools' real `Character` shape**, read from the sibling repo at
   `/Users/gvh/Development/travtools/apps/travtools-web/src/types/index.ts` (interface
   `Character`, backed by its Supabase `characters` table). **Deviation to record plainly:**
   travtools imports XLSX and exports CSV — it emits no character JSON today, so Spec §21.3's
   "round-trips travtools JSON" can only mean round-tripping a JSON serialization of that shape
   inside Telemetry Engine. Honest and fully testable; not validation against a real travtools
   export. Flag for a later real-format pass if travtools ever gains JSON export.
3. **Minimal `Ship`** (jump rating, fuel capacity, current fuel) so §15's `validateJump` and
   `fuelCost` are real rather than half-implemented. No fuel scoops, refuelling rules, or cargo
   capacity — travtools already owns shipbuilding, and Spec §7.3's "resist academically
   interesting" applies.
4. **Career edges: only those whose target systems exist.** Merchant (reroll one Broker check)
   and the generic "negotiated with MAGGIE" edge fire against M1's real skill-check system.
   Scout (needs M4 exploration) and Agent (needs M5 espionage) are declared in the registry and
   marked deferred — complete data, zero faked mechanics.

## Decisions this card must still settle
- **Sector storage:** where imported sector data lives (IndexedDB alongside the save per Spec
  §18, or a separate store), its schema version, and how it interacts with `contentHashes` and
  INV-3 replay determinism — a campaign replayed after a sector re-import must either produce
  identical results or fail loudly, never drift silently.
- **New fact kinds:** whether importing a character posts facts (funds from muster-out cash,
  Obligation reduction from ship shares — rulebook §13.3) and if so, their exact kinds. Any new
  kind goes through `docs/design/fact-kinds-v0.md` before code, per CLAUDE.md. Note
  `packages/engine/src/render/renderer.ts:149` already records that no obligation fact kind
  exists yet.
- **Trust-mode behavior and copy:** Spec §15 says with no sector data, MAGGIE "accepts the
  crew's count and confirms arithmetic only when asked." Settle what the crew enters, where, and
  the exact MAGGIE-voice lines (TTS-safe, no markup, no exclamation points per
  `docs/design/maggie-voice.md`). `packages/engine/src/render/feed.ts` already renders a
  `"unknown"` distance case — decide whether that is the trust-mode surface or a placeholder.
- **Scope of rulebook §13 in M3:** items 1–3 (manual entry/import, career edges, benefits) are
  in. Confirm items 4–5 (contacts becoming journal seeds, linking events) are deferred — they
  feed patron/incident generation that M3 does not otherwise touch.
- **In-app character creation ("career walk", rulebook §13 preamble) is out of M3.** The
  milestone is BYO characters; confirm and record.
