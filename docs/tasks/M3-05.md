# M3-05 — Real distance drives the information horizon, and trust mode when it cannot

## Objective
A remote market price is stale by the real parsec distance to that world, and survives a player
audit — and with no sector loaded, MAGGIE says so honestly instead of inventing a number.

## Context
This is M3's payoff and its named invariant. `feedAnswer` and `renderFeed`
(`packages/engine/src/economy/market.ts`, `packages/engine/src/render/feed.ts`) already implement
INV-9 correctly, and `feed.ts` already renders a `"unknown"` distance case — but
`distanceParsecs` is a **caller-supplied parameter**. Nothing in the codebase computes it from
data. M1 proved the arithmetic; M3 makes the input real.

Spec §21.3's M3 acceptance requires "INV-9 green over imported sector data" and "trust-mode path
tested with no data loaded" — both land here.

Trust mode per Spec §15: no data → `distance() = 'unknown'` → MAGGIE "accepts the crew's count
and confirms arithmetic only when asked."

**This card also fixes a shipped bug M3-00 found** (`travel-and-import-v1.md` §4): `renderFeed`
currently treats `"unknown"` as "show `marketAt(hex, day)`" — the *current* price of a remote
world, no staleness at all — while `feedLine` says "by the crew's count," implying a count was
used. None is ever passed. A remote world's current price is exactly the impossible information
the horizon exists to prevent, and it is worse than a stale price because it is silently
plausible. Resolve into three states:

| State | Distance used | Feed shows | Line says |
|---|---|---|---|
| **Charted** — sector loaded, hexes known | real `distance()` = d | `marketAt(hex, day − 7d)` | stale by d weeks (unchanged) |
| **Trusted** — no distance, crew supplies count c | c, unverified | `marketAt(hex, day − 7c)` | stale by c weeks, by the crew's count |
| **Uncounted** — no distance, no crew count | none | **no line at all** | she cannot date the figure |

Uncounted must not fall back to the current price. Omitting is the established pattern: goods with
no `market.tick` history are already omitted "rather than rendered with a fabricated price.""

## Amendment (M3-03, 2026-07-26)
`FeedDistance` in `feed.ts` must not stay a second, independent copy of the plugin's distance
union. Re-declare it as an alias of `Distance` from `plugin-api/travel.js`, keeping the
`FeedDistance` name so existing call sites are undisturbed.

The three-state split this card implements (charted / trusted / uncounted, travel-and-import-v1
§4) is a **render-layer** type and belongs here, not in the plugin API — the distinction between
trusted and uncounted is whether the table supplied a count, which arrives at `renderFeed` and
never reaches the plugin. A plugin holding no sector data cannot tell those two apart and must not
be asked to. So define the three-state union in `feed.ts` alongside `FeedDistance`; M3-03 has
already settled that the plugin contract stays two-state, and that decision is not reopened here.

## Acceptance tests
`packages/engine/src/economy/horizon.test.ts` — lead-authored at dispatch. Cases:
- **INV-9 over imported sector data (Spec §21.3):** for sampled world pairs in the fictional
  fixture sector, the price shown for hex H at real distance d equals `marketAt(H, day - 7d)` —
  the price a local observer would have seen that day (property, fast-check)
- a player who "jumps" to H and reads the local price on the arrival day sees exactly the price
  the remote feed showed d weeks earlier — the audit the Spec says must survive
- **trusted state:** a crew-supplied count c actually drives the lookup — the price shown equals
  `marketAt(hex, day − 7c)`, not the current price — and the line marks it as the crew's count
- **uncounted state:** with no sector and no crew count, the good is omitted entirely; no price,
  no fabricated distance, no current-price fallback (this is the shipped bug, and it must fail
  before the fix)
- every trust-mode line is TTS-safe MAGGIE voice and passes `pnpm lint:content`
- distance changing (new sector imported) never retroactively alters an already-rendered
  historical price
