# M3-03 — Engine plugin API: TravelModel, Ship, and character contracts

## Objective
Grow `packages/engine/src/plugin-api` from today's economy-only slice to the interfaces M3 needs
— `TravelModel`, `Ship`, `CrewMember`, `CharacterSchema`, `EdgeDef` — so engine code can consume
travel and crew without ever importing the Traveller plugin.

## Context
`packages/engine/src/plugin-api/index.ts` currently declares only `EconomyPluginApi { goods }`,
and its own comment says the rest of Spec §15's `Plugin` "is out of scope here; each slice is
added incrementally by the task that needs it." M3 is that task. This is the INV-1 boundary: the
engine defines the contract, `plugin-traveller` implements it, and `pnpm build:stub` must keep
passing with `plugin-traveller` deleted.

Frontier work — public interface design, forbidden to workers per CLAUDE.md.

## Closed 2026-07-26

Frontier work, one green commit. **No red commit:** the red step exists to fix a contract before a
worker sees it, and this packet has no worker. A type-level red here would also fail
`pnpm typecheck` workspace-wide rather than one assertion, breaking the gate for every other
packet — more than always-shippable trunk contemplates.

Delivered `plugin-api/travel.ts` (`LocationId`, `Distance`, `Ship`, `JumpValidation`,
`TravelModel`), `plugin-api/character.ts` (`CrewMember`, `AttributeDef`, `CharacterSchema`,
`EdgeDef`), both re-exported from `index.ts`, plus 10 contract tests.

Decisions taken, each recorded in PROJECT.md:

- **`JumpValidation` is an extrapolation.** Spec §15 names it and never defines it. It is a
  discriminated union on `outcome` with an explicit `unknown-distance` arm, so an unloaded sector
  yields "I cannot tell" rather than a bare `false` — collapsing it would be the same
  silent-plausibility failure trust mode exists to fix.
- **`Distance` stays two-state**, and M3-05 is amended accordingly.
- **No Traveller vocabulary in the engine.** UPP stats and named skills sit behind
  `CharacterSchema` as plugin-supplied descriptors; only `parsecs` survives, because Spec §15
  writes it into the interface.

One assertion was written wrong and removed rather than weakened: an implementation whose
`distance` returns only `number` *is* legitimately assignable, because return types are covariant
and a plugin that always knows the distance is a valid plugin. The `'unknown'` arm is enforced at
the call site, which a separate assertion covers. The reasoning is left as a comment in the test
so it is not re-attempted.
