# M3-13 — Wire the Traveller plugin and sector-driven distance into the shipped app

## Objective
A person opening `packages/ui-shared`'s shipped app can actually import a sector and a character,
then see a trade-turn market feed whose staleness reflects the real distance between two loaded
worlds — not a hardcoded number. This closes the gap M3-12 found and left open: the milestone's
acceptance items are proven at the module/integration level (`tests/integration/
m3-trade-turn.test.tsx`), but nothing shipped ever reaches that path from the running app.

## Context
Every piece already exists and is tested in isolation:
- `packages/plugin-traveller/src/index.ts` (M3-11) exports `travellerPlugin`, a real `Plugin`
  satisfying Spec §15 — `travel`, `economy`, `careerEdges`, `importCharacter`, all real.
- `packages/ui-shared/src/setup/{SectorImport,CharacterImport,Roster}.tsx` (M3-10) are real,
  tested components that already call `importSector`/`importCharacter` through real file inputs.
- `packages/engine/src/economy/horizon.ts`'s `resolveInformationHorizon` (M3-05) already computes
  the three-state (charted/trusted/uncounted) trust mode from any `{distance}`-shaped object.

None of it is connected. `packages/ui-shared/src/App.tsx` runs its own hardcoded trade-campaign
demo: a fixed `GOODS` list independent of any plugin, and `renderFeed(facts, hex,
currentTime.day, 0, GOODS)` — a **literal `0`** for distance, always. `resolveInformationHorizon`
has no caller in the shipped app at all. Found and documented by `docs/demos/M3.md` (M3-12); see
that file's "Known limit" section and PROJECT.md's 2026-07-26 entry for the full account.

**This is a product-behavior change to the app's entry point** — CLAUDE.md's routing rule and
the two-tier method's review gate both treat that as frontier work with a human gate, not a
worker packet.

## Design questions this card must answer (owner/lead judgment, not a worker decision)
- Where does import happen in the app flow — a setup screen before DOCKSIDE begins, gated behind
  a settings panel, or always-available? Rulebook §13.1 requires both JSON import and manual
  entry to remain first-class; neither may become unreachable.
- What is "home" and "here" for a distance calculation in a single-player-facing demo app with no
  ship-position model yet — pick the simplest honest answer (e.g. the crew's declared current
  hex vs. a traded-at hex) and record it as an extrapolation, per CLAUDE.md's every-turn rule.
- Does `App.tsx` adopt `travellerPlugin.economy.goods` wholesale, or keep its own `GOODS` and only
  wire `travel`/distance? Prefer the smaller change unless the acceptance tests need otherwise.

## Acceptance tests
`tests/integration/m3-app-distance.test.tsx` — lead-authored at dispatch. Cases:
- with a sector imported through the real `SectorImport` component, the app's rendered feed shows
  a staleness tag matching the real charted distance between two loaded worlds — not `0`, not a
  fabricated number
- with no sector imported, the app's feed either shows the honest uncounted state (no price line)
  or offers the crew-count trusted-mode entry — never a fabricated distance (Spec §15, INV-9)
- a character imported through the real `CharacterImport` component appears in the app's own
  crew-facing state (whatever `App.tsx` exposes for it), not just in an isolated component test
- the existing `tests/integration/trade-campaign.test.tsx` walkthrough still passes unmodified —
  this card extends the app, it does not regress the already-real trade-turn flow
- no console error at any point (matching M2.md's walkthrough pass criteria)

## Verification
- `pnpm test && pnpm test:integration && pnpm typecheck && pnpm lint && pnpm lint:content &&
  pnpm build:stub && pnpm build:pages`
- Manually launch `pnpm dev:shared` and walk through an actual sector + character import once,
  by hand, before marking this card done — this is exactly the kind of UI change BL-10/BL-11
  warn tests alone will not catch

## Non-goals
- A ship-position/navigation model (jump plotting, current-hex tracking) beyond whatever minimal
  state this card needs to pick a "here" and a remote hex for the distance calculation
- Redesigning the trade-campaign phase script or its content files
- Any second plugin

## Do not
- Regress `tests/integration/trade-campaign.test.tsx`'s already-real walkthrough
- Let `packages/engine` import `plugin-traveller` (INV-1) — `App.tsx`/`ui-shared` may depend on
  the plugin directly (already does, per M3-10's amendment); the engine itself still may not
- Ship a fabricated distance in either trust-mode state
