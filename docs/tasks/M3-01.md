# M3-01 — Traveller hex coordinates and parsec distance

## Objective
`distance(fromHex, toHex)` returns real parsecs between two Traveller sector hexes, or
`'unknown'` when either hex is not in loaded data — the arithmetic every staleness figure in M3
is built on.

## Context
Spec §15's `TravelModel.distance(fromHex, toHex): number | 'unknown'`. Traveller sector hexes are
4-digit `CCRR` strings (2-digit column, 2-digit row, e.g. `0101`, `1910`), laid out on an offset
hex grid where odd and even columns are vertically staggered — a naive Chebyshev or Euclidean
distance is wrong and will quietly corrupt every staleness tag downstream. Pure functions, no
I/O, no engine imports.

## Acceptance tests
`packages/plugin-traveller/src/hex.test.ts` — lead-authored at dispatch, worker read-only. Cases:
- `parseHex` accepts `0101`/`3240`, rejects wrong length, non-numeric, column or row out of the
  1..32 / 1..40 sector range, with typed errors
- `distance(a, a) === 0` for every hex in a generated sample
- symmetry: `distance(a, b) === distance(b, a)` (property, fast-check)
- adjacency: all six neighbours of a mid-sector hex are distance 1 — this is the case that
  catches offset-grid mistakes, and must include both an odd and an even column
- known fixed pairs asserted against hand-computed values (bare hex strings, **not** the fictional
  fixture sector — that file is M3-02's owned path and does not exist yet)
- triangle inequality holds across sampled triples (property)
- either hex absent from loaded data yields `'unknown'`, never a number or a throw

## Amendments at dispatch (2026-07-26)

Two things the card left for the worker to infer, now settled — both also stated in the header
comment of `hex.test.ts`, so the contract is readable from either document alone.

**1. What `'unknown'` means at M3-01.** Spec §15 makes `distance()` `'unknown'` when a hex is "not
in loaded data." There is no loaded sector data yet — that arrives in M3-02/M3-04 — so the
condition degenerates to "the string is not a valid sector hex." Sector *membership* layers on in
M3-06, when the `TravelModel` is assembled and has data to consult. Extrapolation, recorded in
PROJECT.md.

**2. `distance` declares `number | 'unknown'` inline; it does not import the engine's `Distance`.**
The engine now owns the canonical union (M3-03, `plugin-api/travel.ts`), but this card's own "Do
not" requires that `hex.ts` need nothing from the engine, and adding a workspace dependency would
move `plugin-traveller` in the `tsc --build` graph — not a change to make inside a worker packet.
Structural typing makes the two compatible with no import; M3-06 proves conformance to
`TravelModel` when it assembles one.

**Exact public surface** (in the test header too, so it is not a guess):

```ts
type Hex = { readonly column: number; readonly row: number };
type HexParseError = "bad-length" | "not-numeric" | "column-out-of-range" | "row-out-of-range";
type HexParseResult = { ok: true; hex: Hex } | { ok: false; error: HexParseError };
function parseHex(raw: string): HexParseResult;   // never throws
function distance(from: string, to: string): number | "unknown";
```

**Dependency added by the lead, not the worker:** `fast-check@^3.23.1` as a devDependency of
`packages/plugin-traveller`. Dependencies are forbidden to workers, so leaving it out would have
made the worker's first action a forced escalation.
