# M3-06 — Ship, jump validation, and fuel cost: completing TravelModel

## Objective
The crew can be told whether a jump is possible and what it costs in fuel, completing Spec §15's
`TravelModel`.

## Context
Spec §15 declares `validateJump(ship, from, to): JumpValidation` and `fuelCost(ship, parsecs):
number`, but no `Ship` type exists anywhere in Telemetry Engine. Per M3-00, the owner scoped this
to a **minimal** ship: jump rating, fuel capacity, current fuel. No fuel scoops, refuelling
rules, or cargo capacity — travtools already owns shipbuilding, and Spec §7.3's "resist
academically interesting" applies here too.

`Ship`'s shape is pinned by M3-03; this card implements against it.

## Acceptance tests
`packages/plugin-traveller/src/travel.test.ts` — lead-authored at dispatch, worker read-only.
Cases:
- a jump of exactly the ship's jump rating is valid; rating + 1 is rejected with a typed reason
- a jump within rating but beyond current fuel is rejected with a fuel-specific reason, distinct
  from the out-of-range reason
- `fuelCost` is monotonic non-decreasing in parsecs and zero for a zero-parsec jump (property)
- `validateJump` to a hex the travel model reports as `'unknown'` returns a typed
  cannot-determine result — never a silent pass, never a throw (this is the trust-mode path)
- `stalenessWeeks(parsecs)` matches Spec §7.2's `7d` days expressed in weeks, for sampled d
- validation is pure: no ledger writes, no mutation of the passed ship
