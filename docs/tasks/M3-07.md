# M3-07 — travtools character import and JSON round-trip

## Objective
A player brings a character built elsewhere: import travtools-shaped JSON and get a `CrewMember`,
and export it back unchanged.

## Context
Spec §21.3's M3 acceptance line: "Traveller import round-trips travtools JSON." Rulebook §13:
"Enter name, UPP, and skills into the roster (or import travtools JSON directly). Skills are used
as-is."

Per M3-00, the target is travtools' real `Character` interface, which lives in the sibling repo at
`/Users/gvh/Development/travtools/apps/travtools-web/src/types/index.ts` and is backed by its
Supabase `characters` table. Fields that matter here: `name`, characteristics
(`str`/`dex`/`end_stat`/`int_stat`/`edu`/`soc`, plus house-rule `chr`/`mor`/`lck`),
`skills: [{name, level}]`, `career`, `rank`, `homeworld`/`homeworld_details`, `finances`,
`contacts`, `lifepath`.

**Recorded deviation (M3-00 decision 2):** travtools imports XLSX and exports CSV — it emits no
character JSON today. "Round-trip" therefore means Telemetry Engine round-tripping a JSON
serialization of that shape, not validation against a real travtools export. Say so in the green
commit message; do not let the Spec's wording imply more than was verified.

## Acceptance tests
`packages/plugin-traveller/src/character.test.ts` — lead-authored at dispatch, worker read-only.
Cases:
- round-trip identity: `export(import(json))` deep-equals the input for every fixture character
  (property over the fixture set)
- a character with only the required fields (name plus characteristics) imports successfully;
  optional fields absent do not throw
- unknown/extra fields present in the input are preserved through the round-trip, or dropped
  explicitly and documented — silently losing a field fails this test
- skills import "as-is" per rulebook §13: no renaming, no level clamping, no reordering
- characteristic modifiers derive per standard 2d6 rules from the characteristic value, checked
  against a hand-written table including the negative and zero cases
- malformed input (missing name, non-numeric characteristic, skills not an array) yields a typed
  error naming the offending field, never a partially-built `CrewMember`
- import is pure: no ledger writes, no clock reads, no randomness
