# M3-10 — Import UI: sector file and character roster

## Objective
A person at the table can actually do both imports — pick a sector file, add a character — from
the shipped UI, without a console.

## Context
M3-04 and M3-07 make import work as functions; nothing yet lets a human invoke them. Rulebook
§13.1 requires both paths: import JSON directly, **or** hand-enter name, UPP, and skills — manual
entry is not optional, it is the "or on paper in 1981" path.

BL-10 and BL-11 are the standing lesson here: this project has twice shipped UI whose tests
passed against fakes while the real path was broken. Component tests are necessary, not
sufficient — the M3-12 walkthrough is what proves it.

## Owned paths
- `packages/ui-shared/src/setup/SectorImport.tsx`
- `packages/ui-shared/src/setup/CharacterImport.tsx`
- `packages/ui-shared/src/setup/Roster.tsx`

## Acceptance tests
`packages/ui-shared/src/setup/import.test.tsx` — lead-authored at dispatch, worker read-only.
Cases:
- selecting a valid sector file shows the imported sector's name and world count; the roster then
  reports real distances rather than trust mode
- a malformed sector file shows a MAGGIE-voice error naming what was wrong, and leaves any
  previously imported sector intact
- importing a character JSON adds exactly one crew member to the roster with the right name,
  characteristics, and skills
- manual entry produces an equivalent crew member to importing the same character as JSON
- with no sector imported, the UI states trust mode plainly and offers the crew-count entry —
  it never displays a fabricated distance
- no referee-scoped value appears in the DOM at any point in either flow (INV-13)
- all new visible text passes `pnpm lint:content` TTS-safety and MAGGIE-voice checks

## Verification
- `pnpm test && pnpm typecheck && pnpm lint && pnpm lint:content && pnpm build:pages`

## Non-goals

- Editing a character after import; portraits; roster persistence across campaigns

## Do not

- Ship any player-visible string unchecked against `maggie-voice.md`
