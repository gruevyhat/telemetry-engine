# M3-09 — Career edges: registry, and the edges whose systems exist

## Objective
An imported character's career grants one edge per session — a Merchant rerolls a Broker check —
and using it is logged.

## Context
Spec §15's `careerEdges: Record<string, EdgeDef>`. Rulebook §13.2: "Careers grant a pillar edge,
once per session: Merchants reroll one Broker check · Scouts ask MAGGIE one free survey question
· Army/Marines take a Boon on one engagement decision · Agents receive one extra legend fact ·
Nobles, Rogues, and everyone else negotiate their edge with MAGGIE at import."

Per M3-00 decision 4, only edges whose target systems exist are implemented:
- **Merchant** — reroll one Broker check, against M1's real skill-check system. Implemented.
- **Negotiated** — the catch-all for Nobles, Rogues, and everyone else. Implemented as a
  recorded, referee-visible grant with no automatic mechanical effect.
- **Scout** (needs M4 exploration), **Agent** (needs M5 espionage), **Army/Marine** (needs M5
  engagement) — declared in the registry, marked deferred, and must never fire in M3.

Complete data, zero faked mechanics.

## Acceptance tests
`packages/plugin-traveller/src/edges.test.ts` — lead-authored and lead-implemented (frontier
work, no worker separation). Cases:
- a Merchant character gets exactly one Broker reroll, ever, per campaign; the second attempt is
  refused with a typed already-used result (session-reset dropped — see resolution below)
- the reroll applies to a Broker check specifically — offered on a Broker check, refused on a
  non-Broker check
- a Scout/Agent/Army character has its edge **declared** (present in the registry, correctly
  named) but attempting to fire it returns a typed deferred result — never a silent no-op and
  never a partial effect
- an unrecognised career falls back to the negotiated edge, not to an error and not to Merchant
- the negotiated edge is usable exactly once (at import), targeting the crew member's own
  `crew.imported` fact
- edge use emits a proposal, never a direct ledger write (INV-6)

## Escalation (2026-07-26) — resolved

Reclassified as frontier work at the dispatch gate. The packet assumed four seams that were not
present: a reroll operation rather than a final reported total, a replayable session boundary,
the runtime `edge.used` kind, and a phase-owned commit path.

**Resolution (2026-07-26), logged in full in `travel-and-import-v1.md` §5.4 addendum and
PROJECT.md:**
- No reroll operation needed: Spec §6, "the engine never rolls for a PC," means a reroll is just
  a second player-reported check via the existing `reportCheck` interpreter method.
- No session-lifecycle substrate exists anywhere (no fact kind, no phase step, no milestone
  scheduled to build one). Inventing one here would repeat §5.3's already-rejected mistake.
  Dropped from this card's acceptance list, deferred with no milestone attached.
- `edge.used` is registered in `kinds-v0.ts` (already catalogued in `fact-kinds-v0.md`); stays
  `public` per the catalog, superseding this card's earlier "referee-visible" phrasing for the
  negotiated grant.
- Negotiated edge's `targetFactId` is the crew member's own `crew.imported` fact.
- `edges.ts` stays free of any `@telemetry/engine` dependency (M3-01/06/07 precedent); the actual
  ledger commit lives in `phases/commits.ts`.
