# BL-08 — Trade-campaign integration test waits for committed phase transitions

## Objective

Restore `pnpm test:integration` without weakening the M1 trade-campaign walkthrough.

## Root cause

The test fires a DOCKSIDE `generate` step and a COMMS step, then immediately reads the next phase
in the same synchronous stack. Both steps use `advanceCommitted()`: Web Crypto commitment hashing
must resolve before the interpreter commits the phase transition and React renders it. The
production path is intentionally asynchronous and the colocated App tests already wait for the
observable campaign signature to change.

Making the UI display a phase before its commitment lands would be the wrong fix. The integration
test must await the same observable phase transitions it already asserts.

## Owned path

- `tests/integration/trade-campaign.test.tsx`

## Verification

- `pnpm test:integration`
- `pnpm test`
- `pnpm typecheck`
- `pnpm lint`

## Do not

- Delete, skip, or weaken the walkthrough
- Replace phase assertions with sleeps
- Make production phase state advance before its committed facts exist
