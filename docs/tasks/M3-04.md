# M3-04 — Sector import, local storage, and offline reuse

## Objective
A user imports a sector file once; the app stores it locally and knows real distances on every
later launch, offline, with replay determinism preserved.

## Context
Spec §15: "a one-time user-driven import ... stored locally (static-hosting compliant, offline
thereafter)." Spec §18 puts persistence in IndexedDB with `{schemaVersion, seedState, facts[],
contentHashes}`. Imported sector data participates in content hashing under the reserved key
`sector:<sectorId>`, and lives in its own `sectors` object store rather than inside the save —
a sector is user content reused across campaigns.

**Amended by M3-00 (`travel-and-import-v1.md` §3): mismatch warns, it does not fail.** In M3
sector data is *presentation* input, not ledger input — distance feeds staleness, which feeds
rendered feed lines, and nothing in M3 commits a distance as a fact. So `derive(facts)` never
reads sector data and INV-3's byte-identical replay is not at risk from a sector change. This
follows the shipped precedent in `loadLegacyV1Save`, which warns on content-hash drift and fails
loudly only on `schemaVersion`. A hard failure here would imply a determinism threat that does not
exist.

Frontier: persistence schema plus an INV-3 boundary.

## Acceptance tests
`packages/engine/src/persistence/sector-store.test.ts` — lead-authored at dispatch. Cases:
- import → store → reload yields byte-identical world records and identical `distance()` answers
- a stored sector survives a simulated fresh launch with no network (no fetch in the read path)
- a campaign saved against sector A and loaded against sector B surfaces a
  `content-hash-mismatch` warning naming the sector, through the existing warning path — it
  neither fails the load nor drifts silently (see Context)
- re-importing the same file is idempotent — no duplicate store entries, same content hash
- no sector loaded is a first-class state, not an error: the store returns an explicit
  "no data" result that drives trust mode

## Non-goals
- The import UI — that is M3-10
- Multi-sector libraries or sector switching mid-campaign

## Do not
- Fetch sector data from the network at runtime; import is user-driven and local (Spec §15)
- Weaken or bypass the existing content-hash mismatch path
