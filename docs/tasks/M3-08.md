# M3-08 — Muster-out cash posts to the ledger

## Objective
An imported character's muster-out cash becomes real campaign state: it arrives as funds the crew
can spend.

## Context
Rulebook §13.3: "Benefits post to the ledger: cash muster-out arrives as funds; ship shares
reduce the Obligation's principal; weapons and gear enter inventory."

Frontier work on two counts: it needs new fact kinds, and only the phase-engine interpreter may
write to the ledger (INV-6) — everything else emits proposals. Note
`packages/engine/src/render/renderer.ts:149` already records that **no obligation fact kind
exists yet**, so M3-00 must catalog whatever this card needs in `docs/design/fact-kinds-v0.md`
before any code lands.

**Amended by M3-00 (`travel-and-import-v1.md` §5.3): cash only.** Rulebook §13.3 also says ship
shares reduce the Obligation's principal — but there is no principal. `obligation` exists only as
a *clock id* (`clock.tick {clockId, delta}`, an integer counter summed by `clocksProjection`);
clocks are counters, not money. Inventing a principal to decrement would build a debt system
sideways through a character-import card. Ship shares and inventory are both deferred to the
milestones that build debt and inventory properly.

The catalog entries this card needs (`crew.imported`, `benefit.cashGranted`) already landed with
M3-00, so no catalog PR is outstanding — but `fundsProjection` must be extended to read
`benefit.cashGranted`; today it sums only `sale.settled` and `purchase.settled`.

## Acceptance tests
`packages/engine/src/economy/benefits.test.ts` — lead-authored at dispatch. Cases:
- importing a character with muster-out cash produces exactly one funds proposal of the right
  amount, and the funds projection reflects it after the interpreter commits
- the funds projection reads `benefit.cashGranted` alongside the existing settlement kinds, and
  existing `sale.settled`/`purchase.settled` behavior is unchanged (regression)
- benefits are **proposals**, not direct ledger writes (INV-6) — asserted by the existing
  ledger-write lint rule plus a direct test that the import path performs no append
- re-importing the same character does not double-post benefits (idempotence by a recorded
  import identity)
- replay determinism: a campaign including an import replays byte-identically (INV-3)
- a character with no benefits posts nothing at all — no zero-value facts

## Non-goals
- Ship shares reducing an Obligation principal, and inventory/gear/weapons posting — both
  deferred with reasoning in `travel-and-import-v1.md` §5.3
- Contacts becoming journal seeds and linking events (rulebook §13.4–5) — deferred to the
  milestone that owns patron/incident generation

## Do not
- Write to the ledger outside the interpreter (INV-6)
- Add a fact kind that is not in `fact-kinds-v0.md` first
