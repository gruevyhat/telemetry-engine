# BL-07 — the social sim's accusation posterior can never cross a disposition's accuse bar, so misattribution rate is always vacuously 0

## Context
Discovered while wiring `packages/sim`'s L2/L3/L5 lineups into the sim CLI for M2-15b's "Done
when: L2/L3/L5 sim runs complete within Spec §21.4's thresholds" (misattribution rate 25-40%).

`packages/engine/src/npc/policy.ts`'s `decideSocial` accusation branch:
```ts
case "accusation": {
  const posterior = 1 / candidates.length;
  if ((disposition === "paranoid" && input.unresolvedDiscrepancies >= 2) || posterior > ACCUSE_BAR[disposition]) return { kind: "accuse", ... };
  return { kind: "decline-accusation" };
}
```
`ACCUSE_BAR` is `{ naive: 2, diligent: 0.75, paranoid: 0.5, loyalist: 2, selfish: 0.9 }`. In
`packages/sim/src/social-cycle.ts`'s `runSocialCycle`, `candidates` is always the other 3 lineup
members, so `posterior` is always a flat `1/3 ≈ 0.33` — below every bar (the lowest, paranoid, is
0.5). The one other trigger, `unresolvedDiscrepancies >= 2`, is hardcoded to `1` in
`runSocialCycle` and only applies to `paranoid` anyway, which isn't in L2's roster (L2/L5 are
loyalist/diligent/naive/selfish — sim-bot-policies.md's own "headline metrics" and "parasite-host
stress" lineups). Net effect: verified empirically over 1000 seeds per lineup (L2/L3/L5), **zero
accusations ever fire**. `packages/sim/src/metrics.ts`'s `socialMetrics` then reports
`misattributionRate: 0` for every lineup — not a measured 0%, but the zero-denominator default of
`rate()` when no ground-truth sample exists at all.

M2-15b's sim CLI checkpoint (`packages/sim/src/cli.test.ts`'s "social sim CLI export" suite,
`packages/sim/src/social-runner.ts`) ships the L2/L3/L5 wiring and asserts what's actually true —
`zeroUniqueAttribution` (INV-5/10) and `allDrawsVerified` (INV-8) — plus an explicit
`accusationSamples: 0` field so the export is honest about the gap rather than reading like a
passing 0% band. It deliberately does not assert the §21.4 misattribution band. Owner-descoped
2026-07-19: closing it needs real posterior concentration from evidence-narrowing (an accusing
bot's confidence should rise as evidence rules out candidates, the "tuned-ambiguity target" §21.4
names), which is content+policy tuning against already-shipped M2-06 code — a different shape of
work than app assembly/sim wiring.

## Tests first
- a `packages/sim` or `packages/engine` test that drives a real (non-flat) posterior into
  `decideSocial`'s accusation branch and shows at least one disposition crossing its bar under
  realistic in-band conditions
- `packages/sim/src/cli.test.ts`'s social sim CLI export suite gains back a real band assertion
  (`misattributionRate` in `[0.25, 0.40]` for L2, gated to release-scale campaign counts per its
  existing note) once samples are non-zero

## Done when
- L2's sim run over a release-scale campaign count (`pnpm sim:full`, N=1000) produces
  `accusationSamples > 0` and `misattributionRate` inside Spec §21.4's 25-40% band
- `packages/sim/src/cli.test.ts` asserts the band again instead of asserting the vacuity count

## Do not
- Do not lower or remove the 25-40% band to make a low sample size pass — the Spec's number is
  the target, not the sim's convenience
- Do not change `ACCUSE_BAR` or the paranoid discrepancy trigger without checking every existing
  `npc/policy.ts` test that pins their current values
